# 옮기기 — 이 형식이 아닌 기존 도메인 문서가 있을 때

여러 파일로 흩어졌거나, 분석·가설·설계가 섞인 문서를 `docs/DOMAIN.md` 하나로 옮긴다. 서식은 템플릿 `templates/DOMAIN.md`를 쓴다(없으면 목적지 · 장면 목록 · 용어 · AS-IS · 불편함 · TO-BE 순서). 원본은 지우지 않는다.

## 절차

1. **원본을 전부 직접 읽는다.** 사용자에게 요약을 시키지 않는다
2. **역할·엔티티·값객체 후보 표를 먼저 보여 준다.** 원본에서 쓰인 말 그대로, 구분 추천과 근거 한 줄씩. 사용자가 이름과 구분을 확정한다 — 이 지도는 사용자가 그려야 나중에 혼자 고칠 수 있다. 너는 겹치는 이름, 사람 이름으로 쓴 행위자, 빠진 기록 엔티티를 짚는다
3. 확정한 이름으로 장면 목록을 세우고, 원본의 사실을 장면별 번호 문장으로 옮긴다
   - 원본에 근거가 있는 사실만 옮긴다. 원본의 해석·가설 검증·설계 판단은 옮기지 않는다
   - 당사자가 실제로 한 말(인용)은 문장 아래 인용으로 남긴다
   - 옮긴 문장 끝에는 `— 확인 전`을 붙인다
   - 원본에 있던 불편함은 「불편함」 표로, 사용자가 이미 고른 개선안은 TO-BE로 옮긴다
   - 원본 경로는 문서 머리의 「출처」에 적는다
4. `SKILL.md`의 「마무리」
5. **확인 루프**: 장면 하나씩 문장을 읽어 드리고 "맞나요?"를 묻는다. 맞으면 `— 확인 전`을 관측 시점으로 바꾸고, 다르면 `edit.md` 방식으로 고친다. 한 세션에 장면 한두 개만. 확인 전 문장이 남아 있으면 다음 세션도 여기서 시작한다
6. 확인이 다 끝나면 `--status`로 AS-IS가 비거나 얕은 장면을 찾아 `interview.md`로 이어 간다. 원본을 어떻게 할지(보관 폴더로 옮기기 등)는 사용자에게 한 번 묻는다
