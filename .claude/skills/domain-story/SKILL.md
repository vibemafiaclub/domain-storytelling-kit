# domain-story — 도메인 스토리 인터뷰·고치기·옮기기·보기

도메인 스토리는 **이 서비스를 만드는 사람이 직접 읽고 고치는 문서**다. 에이전트가 쓰는 작업 기록이 아니다.
사용자가 10분 안에 읽고 "맞다/틀리다"를 말할 수 있어야 하고, 현실이 바뀌면 사용자가 이 문서부터 고친다.
UX·API·DB 설계를 평가하는 정답 기준이 이 문서이기 때문이다.

이 파일에는 모든 모드에 공통인 표기와 「무엇을 할지 고르기」만 있다. **고른 모드의 파일만 읽는다.**

## 표기

```
1. [멤버]가 (제출 형식)에 맞춰 {제출물}을 <올린다>.
2. [운영자]가 요건 미달 [멤버]에게 {제한}을 <건다>. — 26년 10월 29일
```

| 표기 | 무엇 | 판정 질문 |
|---|---|---|
| `[역할]` | 일을 하는 사람 | 이 사람이 하는 일을 다른 사람에게 맡길 수 있나? → 역할이다 |
| `{엔티티}` | 하나하나 구별해 추적하는 대상 | 생기고, 상태가 바뀌고, 나중에 "그 건"을 다시 찾나? |
| `(값객체)` | 값이 같으면 같은 것 | 기간·금액·요건·형식처럼 내용만 같으면 바꿔 끼워도 되나? |
| `<행동>` | 역할이 하는 일 | 문장의 동사. 나중에 기능 이름이 된다 |

- **사람 이름을 행위자로 쓰지 않는다.** 대표 한 명이 접수도 하고 검토도 하면 `[접수 담당]`, `[검토자]`로 나눈다. 사람이 늘면 나뉠 단위가 역할이다. 시스템에 접속하지 않는 사람(거래처·외부 강사)은 역할이 아니라 `{엔티티}`다
- **기록을 빠뜨리지 않는다.** "건다·푼다·승인한다·참석한다"처럼 나중에 누가·언제 했는지 물을 행동은 그 결과를 `{제한}`, `{승인}`, `{참석}` 같은 엔티티로 남긴다
- 외부 도구(카톡·Discord 봇·Zoom 등)는 역할이 아니다. 문장에서 수단으로만 쓴다 ("카톡으로", "Discord에")
- 한 문장에 동작 하나. 두 개면 쪼갠다
- 괄호는 값객체에만 쓴다. 덧붙일 말·관측 시점은 문장 끝 `— ` 뒤에 쓴다
- 감싼 말은 전부 「용어」 표에 같은 이름과 **구분**(역할·엔티티·값객체)으로 있다. 한 대상에 이름은 하나, 그 이름은 **사용자가 가장 자주 쓰는 말**이다. 네가 지은 말을 표준어로 쓰지 않는다

## 쓰지 않는 것

이 문서에는 **지금의 현실**만 둔다.

| 넣지 않는 것 | 대신 |
|---|---|
| 알아낸 과정 ("H4 기각", "이전 판본은 틀렸다", "정정") | 지금 맞는 문장 하나로 고쳐 쓴다. 과정은 git 이력에 남는다 |
| 약어 코드 (Q31, X3, D7 …) | 쓰지 않는다. 불편함 번호 `P1`만 TO-BE와 잇는 데 쓴다 |
| 테이블·필드·API·화면 이름, 영어 엔티티명 | 설계 문서(데이터 모델 등)에 둔다. 여기엔 이름·구분·뜻만 |
| 운영 수치 (회원 500명, 월 50건) | 문장·용어에 넣지 않는다. 장면 아래 「물량·시간」 표나 불편함의 「증거」 칸에 관측 시점과 함께 둔다 |
| 네 해석·추천 | TO-BE에만, 사용자가 고른 것만. 네가 낸 안이면 블록 머리에 `제안: AI`를 단다 |

문장 끝 표시 — 관측 시점 대신, 또는 시점 뒤에 붙인다. `node … --status`가 개수를 센다.

| 표시 | 언제 | 언제 떼나 |
|---|---|---|
| `— 확인 전` | 다른 문서에서 옮겨 와 아직 사용자가 확인하지 않음 | 사용자가 맞다고 하면 |
| `— AI 추측` | 네 추측에 사용자가 "맞다"만 함 | 사용자가 자기 말로 구체적인 예를 대면 |
| `— 전해 들음` | 사용자가 직접 하지 않는 다른 등장인물의 일 | 그 사람에게 확인한 답을 받으면 |

## 무엇을 할지 고르기

먼저 상태를 본다. 문서 위치는 `docs/DOMAIN.md`이고, 다른 곳이면 그 경로를 쓴다.

```
node .claude/skills/domain-story/scripts/domain-view.mjs docs/DOMAIN.md --status
```

위에서부터 처음 맞는 것을 한다. 시작할 때 "이번엔 ○○를 합니다 — 이유" 한 줄만 알리고 바로 진행한다. 사용자가 다른 걸 원하면 그때 바꾼다.

| 상태 | 할 일 | 읽을 파일 |
|---|---|---|
| 사용자가 하고 싶은 걸 분명히 말했다 ("보여줘", "바뀌었어", "옮겨줘", "이 장면 인터뷰하자") | 그것 | 해당 파일 |
| `문서 없음`인데 `docs/` 등에 다른 형식의 도메인·업무 문서가 있다 | 옮기기 | `migrate.md` |
| `문서 없음`, 또는 장면 목록이 0개 | 0단계부터 — `/domain-scan`을 **새 세션에서** 하라고 안내하고 끝낸다 | — |
| 확인 전 문장이 있다 | 옮기기의 확인 루프 | `migrate.md` 5번 |
| AS-IS가 없는 장면, 또는 문장이 빈 AS-IS가 있다 | 그 장면 인터뷰 | `interview.md` |
| 사용자가 현실이 바뀌었다·잘못 알았다고 한다 | 고치기 | `edit.md` |
| 그 외 | 보기 | 아래 |

### 보기

```
node .claude/skills/domain-story/scripts/domain-view.mjs docs/DOMAIN.md
```

브라우저에 색칠한 문서가 열린다(역할 초록 · 엔티티 노랑 · 값객체 보라 · 행동 파란 글자, 확인 전 문장은 점선). 맨 위에 역할·엔티티·값객체·행동 목록, 그 아래 표기 경고가 나온다.
사용자에게는 숫자(역할 n · 엔티티 n · 값객체 n · 경고 n · 확인 전 n)와 경고 상위 몇 개만 짧게 알린다. 경고가 있으면 고칠 안을 바로 낸다.

## 마무리 (모든 모드 공통)

1. `node .claude/skills/domain-story/scripts/domain-view.mjs docs/DOMAIN.md --check` 가 통과할 때까지 고친다
2. diff를 사용자에게 보여 주고 확인받는다
3. 커밋·푸시한다
4. `--status`로 남은 일(인터뷰할 장면, 확인 전 문장)을 한 줄로 알린다
